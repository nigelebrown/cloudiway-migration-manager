# JCF Cloudiway Migration Manager

Linux-hosted console for Rackspace Email to Microsoft 365 migrations through Cloudiway, backed by MySQL with phpMyAdmin for database administration.

## Workflow

1. Configure Rackspace Email API User Key, Secret Key and Customer Account Number.
2. Sign in to Cloudiway and save the existing source and target connector pool IDs.
3. Upload XLSX/CSV users.
4. Run a 5-user pilot.
5. For each user the app checks the Rackspace mailbox, generates a 14-character random password, resets the Rackspace password, creates/reuses the Cloudiway user, gets a MailSelfService token, submits the source username/password, and starts the migration.
6. The dashboard polls Cloudiway MailProgress.
7. After the pilot, the app proceeds in batches of 10. Failures pause automation for review.
8. Authorized admins can search for a user, display the stored encrypted temporary password, or generate a new password and push it to Rackspace and Cloudiway again.

## Security

Do not commit the .env file, API keys, Cloudiway credentials, tokens, or user passwords. Rackspace secrets, generated mailbox passwords and Cloudiway tokens are encrypted at rest with APP_ENCRYPTION_KEY. Use HTTPS and restrict access to authorized administrators. Make the GitHub repository private before production use.

## Input file

Required column: source_email

Recommended columns: source_email, target_email, first_name, last_name

Passwords are generated by the application and should not be supplied in the spreadsheet.

## Linux quick start with MySQL + phpMyAdmin

Recommended deployment uses Docker Compose so the app, MySQL, and phpMyAdmin are installed together.

```bash
git clone https://github.com/nigelebrown/cloudiway-migration-manager.git
cd cloudiway-migration-manager
cp .env.example .env
```

Edit `.env` and set strong values for:

- APP_ADMIN_PASSWORD
- APP_ENCRYPTION_KEY
- SESSION_SECRET
- DB_PASSWORD
- MYSQL_ROOT_PASSWORD

Then start the stack:

```bash
docker compose up -d --build
```

Services:

- Migration app: `http://SERVER-IP:8080`
- phpMyAdmin: `http://SERVER-IP:8081`
- MySQL: internal Docker network only by default

phpMyAdmin login:

- Server: `mysql`
- Username: value of `DB_USER`
- Password: value of `DB_PASSWORD`

The application database is the value of `DB_NAME` (default `cloudiway_migration`).

For a temporary isolated LAN trial over plain HTTP, set `SESSION_HTTPS_ONLY=false`. Before entering real Rackspace or Cloudiway credentials, place the migration app and phpMyAdmin behind HTTPS and restrict phpMyAdmin to administrator IPs/VPN only.

## Cloudiway operations used

POST /ap1/Authentication/Login
GET /ap1/Projects
GET /ap1/Connectors
GET /ap1/ConnectorsPool
GET/POST /ap1/Mail
GET /ap1/Mail/VerifyMailUser/{email}
GET /ap1/MailSelfService/token?objectId=...
POST /ap1/MailSelfService/{token}
POST /ap1/Jobs/StartJobs/5/33
GET /ap1/Mail/MailProgress/{objectId}

## Tests

Run: pytest -q

The automated tests cover password generation/encryption, Rackspace signature construction, Cloudiway headers/token parsing, progress parsing, administrator login, CSV import and dashboard state. Automated tests do not call production Rackspace or Cloudiway. Use the in-app connection tests and 5-user pilot before mass migration.


## Migration safety controls

- Unknown or review-required Cloudiway text statuses pause automation instead of leaving a batch running forever.
- Numeric/undocumented status codes remain active until progress reaches 100%.
- BATCH_TIMEOUT_MINUTES defaults to 1440 (24 hours). A migration that remains active beyond that time is marked timed_out and pauses automation for review.
- Stopped, cancelled, aborted, terminated, and completed-with-warnings states require administrator review.
- A correct administrator password is always allowed even after repeated failed attempts from the same source; the rate limit only throttles additional wrong attempts.


## Database

The application uses **MySQL 8.4**. phpMyAdmin is included only as the web administration interface; it is not the database itself.

Main tables:

- `users` — migration users, encrypted temporary Rackspace passwords, Cloudiway IDs, progress and batch state.
- `settings` — application connection/configuration values, including encrypted secrets.
- `events` — audit trail for password resets, credential operations, failures and administrative actions.
- `runtime` — automation state such as paused/running and pause reason.

Database schema is created automatically when the application starts. MySQL data is persisted in the Docker volume `mysql_data`.
