# JCF Cloudiway Migration Manager

Linux-hosted console for Rackspace Email to Microsoft 365 migrations through Cloudiway, backed by MySQL with phpMyAdmin for database administration.

## Workflow

1. Configure Cloudiway and select the existing Rackspace/IMAP source connector and Microsoft 365 target connector.
2. Upload the full master XLSX/CSV list once. The upload is staged in MySQL; no passwords are generated for the entire list.
3. Open **Migration Workflow** and choose the next quantity (for example 5, 20, or 50) or tick exact users.
4. The app creates an incremental migration batch and a matching **Cloudiway Mail Batch**, then generates passwords only for the selected users.
5. For manual Rackspace bulk reset, download the generated package and import the Rackspace CSV/XLSX in the Rackspace control panel.
6. Upload the same generated CSV/XLSX or administrative password map back to that migration batch. The app verifies the source identity and generated password.
7. Once every selected user is confirmed, the app automatically creates/reuses the Cloudiway mail users, registers source credentials, verifies source/target mapping, and assigns those users to the Cloudiway batch.
8. Start the batch manually or select auto-start when the batch is generated.
9. The dashboard and Logs & Issues page monitor Cloudiway progress and detailed mailbox logs.
10. Return to the same master upload and release the next quantity. A 1,000-user list can therefore be migrated as 20 + 20 + 50 + 100, or any sequence chosen by the administrator.

Each incremental migration batch has its own local batch name and Cloudiway batch ID. The dashboard does not bypass this staged workflow.

## Security

Do not commit the .env file, API keys, Cloudiway credentials, tokens, or user passwords. Rackspace secrets, generated mailbox passwords and Cloudiway tokens are encrypted at rest with APP_ENCRYPTION_KEY. Use HTTPS and restrict access to authorized administrators. Make the GitHub repository private before production use.

## Input file

Required column: source_email

Recommended columns: source_email, target_email, first_name, last_name, computer_number

For the normal Rackspace reset workflows, passwords are generated by the application and should not be supplied in the spreadsheet.

For **Existing source password → Cloudiway only** mode, the spreadsheet must contain `source_email`, `target_email`, and `password`. First/last name and Computer Number are optional reference fields in this mode. AD identity validation, AD writes, Microsoft 365 provisioning/readiness checks, and Rackspace password reset are bypassed. The supplied password is encrypted at rest and registered with Cloudiway as the source mailbox credential. The Microsoft 365 target mailbox must already exist.

## One-click CentOS installation

For CentOS Stream / RHEL-compatible 8 or 9 systems:

```bash
sudo bash -c "$(curl -fsSL https://raw.githubusercontent.com/nigelebrown/cloudiway-migration-manager/main/install-centos.sh)"
```

The installer will:

- install Docker Engine and Docker Compose;
- clone or update the application into `/opt/cloudiway-migration-manager`;
- generate strong application, MySQL, and root passwords;
- create the MySQL database stack;
- start the migration app, MySQL 8.4, and phpMyAdmin;
- open port 8080 in firewalld;
- keep phpMyAdmin bound to localhost by default;
- write the generated initial credentials to `/opt/cloudiway-migration-manager/INSTALL-CREDENTIALS.txt`;
- run an application health check before reporting success.

After installation, browse to `http://SERVER-IP:8080`. For live migration use, put the app behind HTTPS and set `SESSION_HTTPS_ONLY=true`.

## Linux quick start with MySQL + phpMyAdmin

Recommended deployment uses Docker Compose so the app, MySQL, and phpMyAdmin are installed together.

```bash
git clone https://github.com/nigelebrown/cloudiway-migration-manager.git
cd cloudiway-migration-manager
cp .env.example .env
```

Edit `.env` and set strong values for:

- APP_ADMIN_PASSWORD
- APP_ENCRYPTION_KEY
- SESSION_SECRET
- DB_PASSWORD
- MYSQL_ROOT_PASSWORD

Then start the stack:

```bash
docker compose up -d --build
```

Services:

- Migration app: `http://SERVER-IP:8080`
- phpMyAdmin: `http://SERVER-IP:8081`
- MySQL: internal Docker network only by default

phpMyAdmin login:

- Server: `mysql`
- Username: value of `DB_USER`
- Password: value of `DB_PASSWORD`

The application database is the value of `DB_NAME` (default `cloudiway_migration`).

For a temporary isolated LAN trial over plain HTTP, set `SESSION_HTTPS_ONLY=false`. Before entering real Rackspace or Cloudiway credentials, place the migration app and phpMyAdmin behind HTTPS and restrict phpMyAdmin to administrator IPs/VPN only.


The automated tests cover password generation/encryption, Rackspace signature construction, Cloudiway authentication/token handling, Cloudiway batch creation, progress/error parsing, administrator login, CSV/XLSX import, the 1,000-user staged workflow, selecting the next N users, exact-user selection, generating only selected passwords, Rackspace package download/re-upload confirmation, Cloudiway batch assignment, migration start, dashboard batch visibility, and duplicate-preparation protection.

## Migration safety controls

- Unknown or review-required Cloudiway text statuses pause automation instead of leaving a batch running forever.
- Numeric/undocumented status codes remain active until progress reaches 100%.
- BATCH_TIMEOUT_MINUTES defaults to 1440 (24 hours). A migration that remains active beyond that time is marked timed_out and pauses automation for review.
- Stopped, cancelled, aborted, terminated, and completed-with-warnings states require administrator review.
- A correct administrator password is always allowed even after repeated failed attempts from the same source; the rate limit only throttles additional wrong attempts.


## Database

The application uses **MySQL 8.4**. phpMyAdmin is included only as the web administration interface; it is not the database itself.

Main tables:

- `users` — migration users, encrypted temporary Rackspace passwords, Cloudiway IDs, progress and batch state.
- `settings` — application connection/configuration values, including encrypted secrets.
- `events` — audit trail for password resets, credential operations, failures and administrative actions.
- `runtime` — automation state such as paused/running and pause reason.

Database schema is created automatically when the application starts. MySQL data is persisted in the Docker volume `mysql_data`.

```bash
sudo bash -c "$(curl -fsSL https://raw.githubusercontent.com/nigelebrown/cloudiway-migration-manager/main/update-centos.sh)"
```

The updater:

- backs up the MySQL database first;
- pulls the latest `main` branch;
- rebuilds and restarts the Docker stack;
- waits for the application health check;
- automatically rolls the code back to the previous commit if the new version fails to start;
- keeps the latest 10 compressed database backups in `/opt/cloudiway-migration-manager/backups`.

Your existing `.env`, MySQL Docker volume, passwords, and migration data are preserved.


## Rackspace password administration authentication

The app supports two Rackspace authentication modes:

1. **Rackspace Username + Password**
   - The app authenticates the supplied administrator credentials against Rackspace Identity and obtains an `X-Auth-Token`.
   - If a Customer Account Number/RAN is supplied, the app then tests whether that token is also accepted by the Rackspace Cloud Office Email administration API.
   - If the Email API rejects the token with 401/403, the application clearly reports that username/password authentication succeeded but automated mailbox password reset requires Email API credentials for that account.
   - The app will not silently proceed with a reset if mailbox administration permission is not available.

2. **Rackspace Email API User Key + Secret Key**
   - This is Rackspace's documented Cloud Office Email API authentication method.
   - It requires User Key, Secret Key, and Customer Account Number/RAN.

The Rackspace username/password and API secrets are stored encrypted in MySQL using `APP_ENCRYPTION_KEY`.

Rackspace Identity documentation supports password-based authentication for obtaining an `X-Auth-Token`. Rackspace separately documents API-key setup for the Cloud Office Email API, so the username/password mode is intentionally implemented as a capability test before it is allowed to administer mailboxes.


## Existing source password → Cloudiway-only workflow

Use this when the current source/Rackspace mailbox passwords are already known and you do **not** want the application to perform AD work or reset Rackspace passwords.

1. On **New Migration Upload**, choose **Existing source password in Excel — Cloudiway only**.
2. Upload XLSX/CSV containing at least:
   - `source_email`
   - `target_email`
   - `password`
3. The supplied password is encrypted immediately in MySQL. It is not written to the application event log.
4. In **Migration Workflow**, select the next quantity or exact users.
5. The app creates a dedicated Cloudiway Mail Batch, creates/reuses each Cloudiway mail user, gets its self-service credential token, and registers the source email/password from the spreadsheet.
6. No AD account is looked up, created, enabled, changed, or added to a licence group. No Rackspace password reset is attempted.
7. Start the Cloudiway migration manually, or select auto-start for that group.
8. Monitor status and Cloudiway logs from the dashboard.

Because this mode bypasses Microsoft 365 readiness checks, the administrator is responsible for ensuring each target mailbox already exists and is ready before starting migration.

The plaintext upload file itself contains mailbox passwords, so treat it as sensitive material, restrict access, and securely remove local copies when no longer required.

## Manual Rackspace bulk-password workflow

This path is independent of Rackspace API access.

1. Upload the complete source/target user list once.
2. In **Migration Workflow**, enter the next quantity or select exact users.
3. Click **Generate Passwords, Create Cloudiway Batch & Download**.
   - only the selected users receive new random passwords;
   - the selected users are recorded in a dedicated migration batch;
   - that migration batch receives its own Cloudiway Mail Batch ID;
   - the ZIP contains the Rackspace CSV, Rackspace XLSX, and administrative password map.
4. Import the Rackspace CSV/XLSX into **Add/Edit Multiple Mailboxes**.
5. Upload the same generated file (or the password-map XLSX) back to the matching migration batch.
6. The app verifies each returned source identity and password. Users outside that migration batch are ignored/rejected.
7. When all selected users are confirmed, Cloudiway preparation occurs automatically.
8. Start the batch, or enable auto-start when creating it.
9. Repeat with the next quantity from the remaining staged users.

The administrative password map contains email, password, source_email, target_email, first_name, last_name, computer_number, upload_batch, and migration_batch.
