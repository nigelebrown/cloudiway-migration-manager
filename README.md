# Cloudiway Migration Manager

Lightweight Linux-hosted migration console for Rackspace Email -> Microsoft 365 through Cloudiway.

## MVP workflow

1. Sign in to Cloudiway from the web UI.
2. Select the Cloudiway project.
3. Configure Rackspace Email API access (server-side only).
4. Upload XLSX/CSV containing source and target email addresses.
5. Validate users.
6. Run a 5-user pilot.
7. Continue automatically in batches of 10 after the previous batch reaches a terminal state.
8. Reset Rackspace mailbox passwords, submit source credentials to Cloudiway, start migration, and track status.
9. Search for a user, reveal the currently assigned temporary password to authorized administrators, or rotate it again.
10. Retry failed users.

## Security

**Do not commit credentials or API keys to this repository.** Use environment variables / the server-side secrets file.

The password vault uses application-level encryption. The encryption key must be provided through `APP_ENCRYPTION_KEY`.

This repository is currently intended for an internal migration utility. Make the GitHub repository private before adding any environment-specific configuration.

## Run

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
uvicorn app.main:app --host 0.0.0.0 --port 8080 --reload
```

Open http://SERVER:8080.

## Input file

Columns:

- `source_email`
- `target_email`
- `first_name` (optional)
- `last_name` (optional)

Passwords are generated by the application; do not place mailbox passwords in the spreadsheet.

## API notes

Rackspace Email mailbox password rotation uses the Rackspace Email & Apps API mailbox update route.

Cloudiway authentication and job execution are implemented against the production API base. The exact Cloudiway operation for attaching per-user IMAP credentials is isolated in `CloudiwayClient.set_source_credentials()` so it can be finalized against the live Swagger contract without changing the rest of the application.
